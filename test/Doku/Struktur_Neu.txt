# Projektstruktur Karl-Gustav III v1.1.1

## Überblick
Das Projekt ist strukturiert nach dem MVC-Muster (Model-View-Controller) und PlatformIO-Standards.

## Verzeichnisstruktur

### src/
Hauptquellcode des Roboters:
- **Karl-GustavIII-v1.1.1.cpp** - Hauptprogrameintrag (main loop)
  - Initialisierung der Hardware
  - Event-Loop mit drei Betriebsmodi:
    - Update (5ms): Sensordaten auslesen
    - System (10ms): Systemfunktionen & Benutzereingaben
    - Game (variabel): Spiellogik und Taktik

### lib/
Bibliotheken und Komponenten:

#### Bot/
Hauptklasse des Roboters:
- **Bot.cpp / Bot.h**
  - Struktur für Sensor- und Aktuatordaten
  - Zentrale Verwaltungsklasse
  - Versionskontrolle via BOT_VERSION

- **includes.h** - Zentrale Header-Include-Datei

#### Bot/Data/
Daten- und Parameterverwaltung:
- **GlobaleVariablen.cpp / GlobaleVariablen.h**
  - Globale Variablen und Flags
  - Sensor-Messwerte
  - Status-Variablen

- **Parameter.cpp / Parameter.h**
  - Konfigurierbare Parameter
  - PID-Konstanten
  - Kalibrierungswerte
  - Schwellwerte

#### Bot/executiveLayer/
Ausführungslogik:
- **Read.cpp / Read.h**
  - Sensor-Datenbeschaffung
  - IR-Sensor-Abfrage
  - Ultraschall-Sensorik
  - Kompass und Lichtschranke
  - Schalter und Taster

- **Action.cpp / Action.h**
  - Motor-Steuerung
  - Taktik-Implementierung
  - PID-Regler
  - Spiellogik (Ballanfahrt, Toranfahrt, Heimfahrt)
  - Spezialbewegungen (Kicker, Dribbler)

#### BotSimulation/
Simulationssoftware:
- **BotSimulation.cpp / BotSimulation.h**
  - Virtuelle Roboter-Simulation
  - Testumgebung für Algorithmen

#### IR/ und IR_Lib/
Infrarot-Ballsensor-Bibliotheken:
- **IR.cpp / IR.h** - Primäre IR-Ring-Implementation
- **IR_ring.cpp / IR_ring.h** - Alternative Implementation
- **ir_ring_registers.h** - Register-Definitionen
- **bus-interface/**
  - **bus_interface.cpp / bus_interface.h** - Abstraktion der Busschnittstelle
  - **i2c_interface.cpp / i2c_interface.h** - I2C-Implementierung

### test/
Test- und Dokumentationsdateien:

#### test/Doku/
Technische Dokumentation:
- **Struktur_Neu.txt** - Diese Datei (aktuelle Projektstruktur)
- **_doks/** - Markdown-Dokumentation
  - Doku.md - Hauptdokumentation
  - Doku_Table.md - Funktionsübersicht
  - index.md - Dokumentations-Index
  - Doku.txt - Text-Version

- **Board/** - Hardware-Spezifikation
  - Ports_v3.0.txt - Pin-Belegung (v3.0)
  - Ports_V3.5.txt - Pin-Belegung (v3.5)
  - Ports_V4.5.txt - Pin-Belegung (v4.5, AKTUELL)
  - enum_V5.txt - Enum-Definitionen

- **BLDC-MotorTrieber/** - BLDC-Motor-Dokumentation
  - Konfigurationsdateien und Konfigurations-Ideas

- **TeensyPinOut/** - Teensy 4.0 Pinout-Referenzen

#### test/Simulation/
Python-Simulationen:
- **BallAnfahrtSimulation.py** - Simulation der Ballanfahrt
- **Test.py** - Allgemeine Testsuite

#### test/snippets/
Code-Referenzen und Snippets:
- Alte Ballanfahrt und Game-Logik
- Code-Beispiele (Action, Display)
- Portal/Port-Belegung
- Systemkommentare

#### test/ablage/
Archivierte/experimentelle Code:
- **AddressChangerUS.cpp** - Adressänderung für Ultraschall
- **CheckSystem.cpp** - System-Check-Routinen
- **KI_GrundsatzAnsatz.cpp** - KI-Grundlagen
- **debug/** - Debug-Implementierungen
  - debugLDR.cpp
  - ConfigBLDC.cpp

#### test/source/
Historische Quellcode-Versionen zur Referenz

#### test/versions/
Versionsgeschichte:
- Karl-GustavIII-v0.0.0.cpp bis v1.1.1.cpp

### include/
Header-Dateien und Projektdefinitionen (bei Bedarf)

### Configuration Files
- **platformio.ini**
  - Board: Teensy 4.0
  - Framework: Arduino
  - Dependencies: Adafruit BNO055, Pixy2 Kamera

- **makeVersion.py**
  - Automatische Versionsverwaltung

## Abhängigkeiten (Externe Bibliotheken)

1. **Adafruit BNO055** (v1.6.4+)
   - 9-DOF Sensor Fusion (Kompass, Gyro, Accelerometer)

2. **Pixy2 Kamera** (v1.0.4+)
   - Kamerainterfacing für Torerkennung

3. Arduino Framework für Teensy 4.0
   - Built-in Funktionen (Serial, Wire, etc.)

## Hardware-Zielplattform

**Teensy 4.0 Microcontroller**
- Dual-Core ARM Cortex-M7
- 600 MHz
- 1 MB RAM
- Ideal für Echtzeit-Robotersteuerung

## Build & Deployment

1. **PlatformIO installieren**: Extension in VS Code
2. **Project öffnen**: `platformio.ini` wird automatisch erkannt
3. **Bauen**: `platformio run` oder Build-Button
4. **Hochladen**: `platformio run --target upload`
5. **Monitor**: `platformio device monitor`
